# Friseur Ulrich — сайт салона

Сайт парикмахерской с онлайн-записью, отзывами и личным кабинетом.
Чистый **Node.js** (без фреймворков) + один пакет `nodemailer`.

- Главная страница: `index.html` (адаптив: телефон / планшет / ПК)
- Личный кабинет: `/admin` (заявки, отзывы, модерация, выгрузка CSV)
- API: `/api/bookings`, `/api/reviews`, `/api/admin/*`
- Проверка живости: `/healthz`

## 2. Залить в интернет на бесплатный хостинг

Сайту нужен **Node.js-хостинг** (не хватит Vercel/Netlify/GitHub Pages —
это только статика, там не заработают запись, отзывы и кабинет).

### Рекомендую: Render.com — бесплатно, ссылка вида `https://friseur-ulrich.onrender.com`

1. **GitHub.** Зарегистрируйтесь на [github.com](https://github.com) → `New repository`
   (имя `friseur-ulrich`, галочку README можно не ставить) → `Create`.
   На странице репозитория: `uploading an existing file` → перетащите **все файлы
   из папки проекта**, КРОМЕ `node_modules` и `data` → `Commit changes`.
2. **Render.** [render.com](https://render.com) → войдите через GitHub →
   `New +` → `Web Service` → `Build and deploy from a Git repository` →
   выберите свой репозиторий.
   Настройки (подставятся сами из `render.yaml`, если нет — вручную):
   - **Runtime**: Node
   - **Build Command**: `npm install`
   - **Start Command**: `node server.js`
   - **Instance Type**: `Free`
   - **Region**: Frankfurt
3. **Environment Variables** (добавьте в панели `Environment`):
   | Переменная | Значение |
   |---|---|
   | `ADMIN_USER` | ваш логин в кабинет (например `ulrich`) |
   | `ADMIN_PASS` | **надёжный пароль** |
   | `SESSION_SECRET` | любая длинная случайная строка |
   | `NODE_VERSION` | `20` |
   - Почта (необязательно, см. раздел 4): `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `MAIL_TO`
4. `Create Web Service` → подождите 1–2 минуты → вверху будет ссылка —
   **её и отправляйте кому угодно**.

> ⚠️ **Бесплатный план Render засыпает** после ~15 минут без посетителей, первый
> вход после сна занимает ~50 секунд (страница может показать «загрузку» —
> просто обновите). Файлы в `data/` на бесплатном плане могут **обнулиться**
> при передеплое/перезапуске — для тестового показа это нормально;
> для «всерьёз» нужен платный диск ($1–7/мес) или VPS.

### Альтернатива: Koyeb / Fly.io (есть `Dockerfile`)
Koyeb: `New App` → GitHub-репозиторий → он сам найдёт `Dockerfile` → Free.
Fly.io: нужна карта для проверки, разворачивается командой `fly launch` в папке проекта.

### «Прямо сейчас, без git» — временная ссылка на 2 часа
Пока компьютер с проектом включён:

```powershell
npm start
npx localtunnel --port 8099
```

Он покажет ссылку вида `https://xxx.loca.lt` — она живёт, пока идёт команда.
Проще и стабильнее для показа — всё же Render из шага 2.

## 3. Личный кабинет

Вход: `https://ваш-адрес/admin`
- **Заявки** — все записи с формы (статусы: новая / подтверждена / выполнена / отменена)
- **Отзывы** — новые приходят как `pending`; после «Одобрить» появляются на сайте
- **CSV** — выгрузка заявок и отзывов в Excel
- **Пароль** меняется только через переменную `ADMIN_PASS` на хостинге (и перезапуск).
  Никогда не оставляйте `admin123` на публичном адресе.

## 4. Почта (чтобы заявки приходили на email)

Без настроек заявки сохраняются в кабинете — сайт работает.
Чтобы дублировать на почту, добавьте на хостинге переменные (пример — Gmail):

| Переменная | Значение |
|---|---|
| `SMTP_HOST` | `smtp.gmail.com` |
| `SMTP_PORT` | `465` |
| `SMTP_SECURE` | `true` |
| `SMTP_USER` | ваша почта |
| `SMTP_PASS` | **пароль приложения** (не обычный пароль Gmail: Google-аккаунт → Безопасность → Пароли приложений) |
| `MAIL_TO` | куда присылать (можно = `SMTP_USER`) |
| `MAIL_FROM` | необязательно, имя отправителя |

В логах сервера при старте будет строка `Почта: SMTP настроен…` — значит работает.

## 6. Проверка перед показом клиенту

```powershell
npm start
powershell -NoProfile -ExecutionPolicy Bypass -File .qa\e2e.ps1
```
В консоли — `23/23 PASS`. Плюс вручную: открыть сайт на телефоне, отправить запись,
зайти в `/admin`, одобрить отзыв, проверить, что он появился на главной.

## 7. Обновление сайта

- **Render из GitHub**: изменили файл → в GitHub `Commit` (или `git push`) →
  Render пересобирает сам.
- **Без git**: `Manual Deploy` → `Clear build cache & deploy` (файлы в GitHub
  всё равно нужно обновить).

## 8. Ограничения тестовой версии

- Данные — JSON-файлы, не база данных: для тестового показа хватает,
  для постоянной работы с ежедневными записями лучше платный диск/VPS.
- Немецкая версия сайта — следующий шаг (сейчас всё на русском).
- Авторизация — на cookie с подписью, без хеш-паролей в базе: для теста достаточно,
  перед «боевой» передачей стоит перейти на нормальную сессию.
